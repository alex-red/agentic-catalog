# Reference-to-interface: human-focused assessment

Reviewed October 29, 2026 (America/Edmonton) by Codex, an AI curator and the workflow's author. Rubric: [human-v1](../ratings.md). This is an author source review, not independent calibration or behavioral evaluation.

## Context and baseline

For developers reconstructing a supplied interface or applying an observed design language to new product content. The baseline is `frontend-design` with manual reference notes and rendered screenshots. The linked `design-dna` alternative structures style extraction and generation, but its required schema encourages completion by inference and its automated verifier covers palettes rather than full fidelity. [Research and source review](../research/2026-10-29-catalog-scout-5.md), [Design DNA assessment](2026-10-29-design-dna.md).

Installed image and browser tools support observation and comparison. This assessment does not claim that every host lacks similar guidance. `human-interface-design`, `interface-design`, `webapp-testing` and `evidence-to-flow-ux` retain their existing jobs; none is required by this workflow.

## Inspection and provenance

Read the complete new `entries/workflows/reference-to-interface/WORKFLOW.md`, metadata and MIT license. These repository source files define the assessed version; later changes require reassessment. The installable directory contains the complete procedure, its metadata and license, with no runtime scripts, external templates or supporting-resource dependency.

The independently written method draws on the previously inspected pinned MIT sources listed in `inspiredBy`: Design DNA's extraction/application split and UXKIN's measure/build/compare sequence. It includes original uncertainty labels, separate acceptance modes, reference acquisition for title-only requests, task mapping, capture-condition checks and an explicit evidence boundary. No upstream prose, scripts or artwork is copied.

The Cyberpunk example is a hypothetical application, not a completed recreation or research finding about that game's visual system. No asset, reference search, implementation, screenshot comparison, participant study or activation trial was performed for this admission.

## Limits, disposition and next evidence

Admit as an **adapted experimental workflow**, evidence **reviewed**. No source-inspection blocker is assigned; no required runtime remains unread. Missing references or a render path constrain a consumer task's conclusions, rather than authorizing invented measurements. The three-round default bounds correction effort without promising convergence; remaining gaps must accompany delivery.

The procedure can guide observation and implementation but cannot make a static image reveal source interactions or prove representative human usability. Exact font metrics, color values and responsive behavior may remain uncertain. No quality gain, correction-time reduction or trigger reliability has been measured.

Next, compare this workflow with the named baseline on one exact-screen reconstruction and one style-transfer task. Keep references, content and capture conditions comparable; record correction effort, deviations, task/state coverage and any unsupported source claims. Include a missing-reference case to examine whether uncertainty remains explicit. Record actual trial evidence before changing the evidence level or treating the author rating as calibrated.
