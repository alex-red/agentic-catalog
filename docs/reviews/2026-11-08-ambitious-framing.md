# Ambitious framing: human-focused assessment

Reviewed November 8, 2026 by Claude, an AI curator and the skill's author. Rubric: [human-v1](../ratings.md). This is an author source review, not independent calibration or behavioral evaluation.

## Context and baseline

For developers starting a substantial task whose literal wording undersells the outcome, or who explicitly ask the agent to be more ambitious. The baseline is a plain instruction such as "be more ambitious" or "act like an expert", plus host plan mode. `grilling` stress-tests a plan the person already has; `explore-plan-implement-review` sequences execution. Neither reframes the request itself.

## Inspection and provenance

Read the complete source essay, Felix Rieseberg's "How to be more ambitious: A tutorial for humans with models" (October 13, 2026), and the new `entries/skills/ambitious-framing/SKILL.md`, metadata and MIT license. The essay has no stated license, so the entry is adapted: the procedure is written in original prose, examples and prompts are paraphrased, and no passage is reproduced.

The essay's four ambition types are kept except Speed, which the author also sets aside. Its altitude rungs, four depth questions, outside-judge requirement, nouns-to-verbs technique, crew assembly and warning against role-play map to procedure steps. Catalog additions: the propose-then-act scope boundary, the honest-reporting rule for hard targets, the explicit access-gap listing and the menu template. The essay's self-efficacy history section motivates the method but is not operational, so it is omitted.

## Grades

| Criterion | Grade (0–4) | Rationale |
| --- | ---: | --- |
| Practical value | 3 | Turns a vague "think bigger" into concrete rungs, raw-material and method questions, and an outside check. Gain over a plain prompt is unmeasured. |
| Dependability | 2 | The method is coherent and demands outside verification, but hard-target and "keep going" framing can push wasted effort or overclaiming; the honest-reporting rule mitigates without guaranteeing it. |
| Cognitive ease | 3 | One compact menu with a recommended prompt; the person chooses a rung rather than reading a survey. |
| Human control | 3 | Scope expansion requires the person's choice and gaps are named. Multi-agent crews depend on the host and cost approval. |
| Adoption cost | 3 | Single file, no dependencies. Full depth and range need data access and an execution environment the consumer may lack. |
| Compatibility | 3 | Host-neutral; defers to project scope rules. Overlaps plan mode and planning skills. |
| Upkeep | 3 | Small and self-contained; statements about current model limits (self-judging, abstraction ceilings) may age. |

Weighted aggregate: **7.0/10** (280/40). Provisional author judgment.

## Limits, disposition and next evidence

Admit as an **adapted experimental skill**, evidence **reviewed**. No blocker is assigned. The method raises the ceiling of a request but does not make results correct; its value depends on the outside check actually being run.

Next, compare against the plain "be more ambitious" baseline on two tasks: one outcome-driven analysis and one engineering task with a runnable check. Record whether the reframe surfaced decisions or methods the baseline missed, how often the person accepted the expanded scope, extra effort, and any unsupported success claims. Also record trigger behavior on small fixed-scope requests, where the skill should stay quiet.
